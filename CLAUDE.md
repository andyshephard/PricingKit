This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

PricingKit is a Next.js application for managing in-app product and subscription pricing across Google Play Store and Apple App Store. It enables developers to view, edit, bulk-update and export pricing by region with currency conversion and multiple pricing strategies: PPP (World Bank), Big Mac Index, Netflix Index and Custom (a per-territory multiplier table).

## Architecture

### Tech Stack
- **Framework:** Next.js 16 (App Router) with TypeScript; deployed to Cloudflare Workers via `@opennextjs/cloudflare`, also runs on Node with `npm start`
- **UI:** Tailwind CSS 4 + shadcn/ui (New York style) + Radix UI
- **State:** Zustand (client state with localStorage persistence) + TanStack React Query (server state)
- **Forms:** React Hook Form + Zod validation
- **APIs:** hand-rolled `fetch` clients, no store SDKs (there is no `googleapis` dependency). Google Play: service-account JWT signed with Web Crypto and exchanged for an OAuth access token (`googlePlayFetch` in `/lib/google-play/client.ts`). Apple: ES256 JWT (`appleApiRequest` in `/lib/apple-connect/client.ts`).

### Data Flow & State Management

**No database** - stateless architecture:
- Sessions are cookie-only; nothing is written server-side. A session cookie is `"v3." + base64url(iv + ciphertext)`: AES-256-GCM over the envelope `{ v: SESSION_VERSION (default "1"), typ: "google" | "apple", iat, exp, creds }` (`session-envelope.ts`), with additional data `pricingkit/session/v3|<cookie base name>|<session version>`. The key is HKDF-SHA-256 over the decoded `ENCRYPTION_KEY` bytes, derived once per process. `openSession` checks the envelope after decryption: type, version, `exp - iat` at most 24 hours, `iat` not in the future, not expired, credential shape. `exp` is absolute: never extend it when re-writing a cookie (`sealSession(..., { exp })`). Google sessions keep `client_email`, `private_key_id`, `private_key`, `project_id` only; a cookie over 3800 bytes is refused (`CookieTooLargeError`), never written. Routes read and write cookies only through `src/lib/session.ts` (`readSessionCookie`, `writeSessionCookie`, `readAppCookie`, `writeCookie`, `clearCookie`), never `cookies().get/set/delete` directly.
- Cookie names get the `__Host-` prefix in production (`cookieName()`; `Secure`, `Path=/`, no `Domain`); under `next dev` and in tests they are plain. Deleting means writing an expired cookie with the same attributes (`clearCookie`), since a plain delete can't replace a `__Host-` cookie.
- Legacy cookies (v2: HKDF over the key text, no envelope; v1: PBKDF2 per cookie) and the old cookie names are read until `LEGACY_SESSION_CUTOFF` (2026-11-10, `encryption.ts`) and while `SESSION_VERSION` is unset, after a strict base64 and length check (no key derivation for junk), and re-written as v3 under the new name by `readSessionCookie` / `readAppCookie` (best effort), with `exp` = min(now + 24 h, cutoff). A v3 envelope found under an old (unprefixed) name is refused: v3 is only written under `__Host-` names, so it was planted (cookie tossing). After the cutoff, delete the legacy path (`openLegacy`, the v2/v1 keys, `readCookie`'s old-name fallback).
- `ENCRYPTION_KEY` is required everywhere except `next dev`, and must be base64/base64url of at least 32 bytes with at least 16 distinct byte values (`MIN_ENCRYPTION_KEY_DISTINCT_BYTES`; random keys never come close, repeats do) (`encryptionKeyProblem()`: `missing` | `weak`). It is a format check, not a randomness test; docs must not claim otherwise. Otherwise (outside `next dev`), creating a session throws `MissingEncryptionKeyError` (message from `encryptionKeyMessage()`) and reading one returns null (signed out); login checks `canStoreSessions()` before any store call. Under `next dev` (`NODE_ENV=development`) a weak key works with a warning, and without a key the envelope is stored unencrypted (`p3.`).
- Short-lived store tokens (Apple JWTs, Google access tokens) are cached in memory in a 50-entry LRU keyed by a SHA-256 of the full credential, so users of a shared instance never share a token.
- Exchange rates (`lib/exchange-rates/client.ts`): 6-hour cache in memory, then Cloudflare's shared Cache API (`caches.default`, guarded: absent on Node and in tests), then on Node `.exchange-rates.json` in the working directory. Only operator-key (`OPEN_EXCHANGE_RATES_APP_ID`) misses share one in-flight request and only their failures are remembered 5 minutes (stale data or the same error meanwhile, no new request); a user-key fetch (`fetchWithUserKey`) runs on its own and never touches `inFlight` or `lastFailure`, so a bogus key can't poison other visitors; upstream requests time out after 10 s and their error bodies are never passed on. `forceRefresh` goes upstream only with the user's own key (Settings cookie): it never spends `OPEN_EXCHANGE_RATES_APP_ID`. World Bank PPP (`getPPPMultipliers`) has the same in-flight sharing and 5-minute failure cache, and honours a forced refresh at most once per 10 minutes per instance.
- Client auth state persisted to localStorage via Zustand

**API Authentication:**
- Google Play: Service account JSON credentials
- Apple: JWT with private key (.p8 file), issuer ID, and key ID
- Login (`/api/auth`, `/api/apple/auth`) and app switching (`/api/active-app`) only issue GET requests to the stores. Do not add a write "permission probe": a missing write permission surfaces on the first real edit.

### Store API errors, retries and budgets
- Both clients throw subclasses of `ApiError` (`AppleApiError`, `GooglePlayApiError`) shaped `{ status, code?, platform, retryable, details? }`. Normalise unknown errors with `toApiError()`; never `String(err)` (it yields `[object Object]`).
- `appleApiRequest` and `googlePlayFetch` retry 429, 5xx and network errors with jittered exponential backoff (default 4 attempts) and honour `Retry-After` up to 60s, failing fast above that. Apple POSTs (creates) retry only 429, and their other failures are `retryable: false`, because a create that timed out or got a 5xx may already exist. Apple's `X-Rate-Limit` header is tracked: a 429 is not retried when it reports 0 requests remaining. Later requests are only stopped when the caller passes a `RequestBudget` (no route does yet).
- For long loops, pass a `RequestBudget` via the `budget` option. Once spent it throws `ApiError(429, 'BUDGET_EXCEEDED')` before sending. Budgets hold no module-level state, so create one per run or user.
- Every store helper in `lib/apple-connect` and `lib/google-play` takes an optional trailing `ctx: RequestContext` (`{ budget }`) and passes it to every request it makes, including pagination and the app lookup. New helpers must do the same. The bulk routes (Apple subscription PATCH, price-points/batch, clear-scheduled, Apple IAP PATCH, `/api/bulk`) create one `RequestBudget` per request.
- No unbounded `Promise.all` over store requests: use `mapWithConcurrency` (`lib/pricing/concurrency.ts`). Apple list reads use `appleListPages`/`appleListAll`; never hand-roll a `links.next` loop (it must keep the cursor).
- Apple routes map the `ApiError` status through `appleErrorResponse` (401/403/404/409/429/5xx) instead of a blanket 404/500. The Google subscription base-plan PATCH and the Google region DELETEs (product and base plan) pass Google's 400/409/412 through. Public endpoints return generic messages and log the raw error server-side. Other Google detail-route errors still become a 500 carrying the upstream message.

### Store write rules
- Google base plan PATCHes send `regionsVersion.version` from the caller (CLI plans record Play's current one in `op.options.regionsVersion`), else the resource's (Play's Subscription has none per the discovery document), else Play's current one from `convertRegionPrices().regionVersion` (`fetchCurrentRegionsVersion`); never a hard-coded constant: none at all refuses the edit (`NO_REGIONS_VERSION`).
- Google region edits change only the regions passed in. Everything else (other regions, availability, `newSubscriberAvailability`, other base plans) is sent back exactly as fetched. Never fill in missing regions, force availability on, or invent prices. `regionsVersion` comes from the fetched resource; the constants in `products.ts` / `subscriptions.ts` are fallbacks only.
- Region delete removes exactly one region. If Google refuses, its reason is passed through to the client.
- Apple subscription price edits create the new price before deleting the scheduled price it replaces, and report per-territory outcomes.
- `/api/bulk` is two steps: `dryRun: true` returns each product's / base plan's changes (`oldPrice` / `newPrice` as exact `"<currency> <decimal>"`) and writes nothing; a write needs `expectedPrices` (`{ "<id>" | "<id>/<basePlanId>": { <region>: <oldPrice> } }`, the bulk modal sends the preview's) and changes only regions whose price is still exactly that (`PRICE_CHANGED` / `NOT_PREVIEWED` skips otherwise). The previewed prices also go to the write helpers as `expected` (`updateInAppProductPrices(..., ctx, { expected })`, `updateBasePlanPrices(..., ctx, { expected })`, `lib/google-play/expected-prices.ts`), which compare them with their own fresh read just before the PATCH and refuse the whole write with `PRICE_CHANGED` (409). Items are deduplicated on product / base plan (a subscription item and one of its base plans write that base plan once). `fixed` needs `currency` and changes only regions billed in it (`OTHER_CURRENCY`); value >= 0; ids, base plan ids and regions go through the validation schemas. Bulk results report skipped items and regions, and `duplicates` lists the items (`REPEATED_ITEM`) and base plans (`BASE_PLAN_COVERED`) dropped as already covered. A run that wrote nothing is a failure, not "Successfully updated 0 items". A subscription item without `basePlanId` expands to one result per base plan (`total` counts results); a subscription with no base plans, or an unknown `basePlanId`, is a failed item.
- `/api/export` is read-only: the route may import only store read functions (enforced by `src/app/api/export/__tests__/route.test.ts`).

### API Route Patterns
- RESTful: `GET/PATCH/DELETE /api/products/[sku]`
- Platform-specific: `/api/products` (Google) vs `/api/apple/products` (Apple)
- Error codes: 401 (auth), 403 (permission), 404 (not found), 422 (e.g. Apple IAP update without a base territory price), 429 (rate limit)
- Routes get credentials only from `@/middleware/auth`; never define a cookie helper in a route file or import one from another route (`src/app/api/__tests__/auth-helpers.test.ts`).
- Every `POST`/`PUT`/`PATCH`/`DELETE` handler starts with `const crossSite = rejectCrossSite(request); if (crossSite) return crossSite;` and reads its body only with `readJsonBody(request, SMALL_BODY_LIMIT | LARGE_BODY_LIMIT)` (`src/lib/request-guard.ts`: `Sec-Fetch-Site` same-origin or a matching `Origin`, requests with neither are non-browser and allowed; `application/json` only; 16 KB for sign-in, app switch and settings, 1 MB for the rest). Never read a request body directly in a route (`src/app/api/__tests__/route-guards.test.ts` checks both with the TypeScript compiler and type checker: handlers however exported, `rejectCrossSite` resolved to the `@/lib/request-guard` export, body reads and `.body` on a `Request`/`NextRequest` under any name or alias, destructuring included). Login routes check `canStoreSessions()`, the Google key size (`isAcceptedServiceAccountKey`: RSA 2048-4096, parsed from the DER before any import) and `signInAttempts` before contacting the store; package names and bundle IDs go through `packageNameSchema` / `bundleIdSchema`.
- Public, no auth: Index Checker page at `/index-checker`, `GET /api/ppp` and `GET /api/exchange-rates`. Their `?refresh=true` needs a valid Google or Apple session (401 otherwise), and even then re-fetches exchange rates only with the user's own key and World Bank PPP at most every 10 minutes. Saving an Open Exchange Rates key (`POST /api/settings/exchange-rates`) tests it upstream; without a session that is limited to 50 per instance per 10 minutes, and 5 per client when `TRUSTED_CLIENT_IP_HEADER` is set. Under `next dev` a plaintext session cookie can be forged to skip the limit (dev only).

### Currency & Pricing
- **Pricing strategies:** `'direct' | 'ppp' | 'bigmac' | 'netflix' | 'custom'` — defined in `/lib/pricing/strategies.ts` (`PricingStrategy` type + `calculateRegionalPrice` switch). Import from `@/lib/pricing`. `custom` takes a per-territory multiplier relative to the base region (`relativeMultipliers`); the bulk modals use `components/pricing/custom-multipliers.tsx`, and price only territories in the table (never a silent 1.0).
- **Reference data freshness** (`freshness.ts`): every built-in data set has a date in `REFERENCE_DATA` (Apple tiers via `apple-connect/price-tier-meta.ts`, updated by the regeneration script). Update the date whenever you refresh a data set. `/api/ppp` returns `metadata.freshness`, per-region `pppYear`/`pppStale`, and applies `?pppStale=cap|inflate&pppMaxAge=` (CPI from World Bank FP.CPI.TOTL, `getCpiSeries`: one shared in-flight request, results cached 24 h, failures 5 min; a country and the US are compared over the same years, `latestCpiYear`).
- **Multiplier convention:** all indexes clamp to `[0.1, 2.0]` (live World Bank PPP included), normalized to base region (not US directly)
- **Missing exchange rates:** `getExchangeRate` never falls back to 1.0. A region without a rate gets `error: 'MISSING_EXCHANGE_RATE'` and a zero price; `filterApplicablePrices()` drops it and the UI shows "No exchange rate". Never apply a flagged price.
- **Rounding:** `calculateNewPrice` `round` rounds down to the nearest price ending at or below the current price; zero-decimal currencies (JPY, KRW, ...) get whole-number results.
- **Canonical territories:** `getSupportedAppleTerritories()` in `/lib/apple-connect/territories.ts` — use for coverage checks when adding new indexes
- **Exchange rates:** Open Exchange Rates API with caching (see above)
- **PPP multipliers:** Static `PRICING_INDEX` in `/lib/pricing/indexes/ppp.ts`; partial fallback to `FALLBACK_EXCHANGE_RATES` with UI banner when API fails
- **Apple price tiers:** Large mapping file (`price-tier-data.ts`, 400K+ lines), regenerated with `scripts/fetch-apple-price-tiers.ts` (read-only, real credentials, run by hand and review the diff)

### Price export
- `/lib/export` turns fetched store state into a `PriceExport` (`schemaVersion: 1`, see `types.ts`). Amounts are canonical decimal strings built without floating point; CSV is RFC 4180 with formula-injection guarding. Bump `PRICE_EXPORT_SCHEMA_VERSION` on any breaking change.
- `GET /api/export?platform=google|apple&type=inapp|subscription&id=...&basePlanId=...&format=json|csv` (`basePlanId` required for Google subscriptions). UI: `ExportPricesButton` on product and subscription detail pages.

### Pricing core (`src/lib/pricing`)
- **Framework-free.** No `next`, `react`, web-app, adapter or network imports, directly or transitively. `src/lib/pricing/__tests__/core-boundary.test.ts` walks the import graph; an ESLint rule blocks direct imports. Only `zod` is allowed as a package. Store I/O belongs in `src/lib/adapters`.
- **Money is Decimal strings** (`decimal.ts`), compared and computed on BigInt-scaled integers. `decimalFromNumber()` is the only float-to-Decimal boundary (strategy output). Never put a JS number amount in a plan, run or state file.
- **Plans** (`changeset.ts`): `ChangeSet` (`kind: pricingkit.changeset`, written as `schemaVersion: 3`, read 1, 2 and 3; a higher version is refused as "written by a newer PricingKit"; the hash covers app + ops only. `changeSetHash` is SHA-256 (`sha256Hex` in `refs.ts`, pure TS so the core stays synchronous and dependency-free) truncated to 32 hex digits (`confirmHash`) for every schema version: never let a file's `schemaVersion` select the hash. `confirmHashSchema` (32 hex only) checks run logs, workspace indexes and the web apply route. `fnv1a64` remains only for idempotency keys, never a confirm hash) of `BasePriceOp`s (`setPrice`, `schedulePrice`, `deleteScheduled`, `removePrice`), each with `before`, `after` and `idempotencyKey` (`computeIdempotencyKey`). `parseChangeSet` enforces one op per product/territory/slot, Apple ops naming a price point, and matching keys. Offer ops (`offer-ops.ts`) are the other op shape in `ops` (`ChangeOp = BasePriceOp | OfferOp`; read base ops with `basePriceOps()`). Availability and cohort kinds are reserved and refused until their phase. Bump `CHANGESET_SCHEMA_VERSION` on breaking changes.
- **Undo and preserveCurrentPrice** (`inverse.ts`): an App Store inverse that raises a price (undoing a decrease) gets `preserveCurrentPrice: true` even if the original op had `false`, and `buildUndoChangeSet` adds a plan warning saying so; inverses that lower a price, and Google ops, keep the option as it was.
- **Executor** (`executor.ts`): reads each product once, then skips ops already at `after`, applies ops at `before`, and fails anything else with `STATE_CHANGED` without sending. Resume by passing the saved `ApplyRun`; undo with `buildUndoChangeSet`. The run is published to `onUpdate` before every write (attempt recorded) and after; a failed save stops the run (`PERSIST_FAILED`). A unit starts only if the budget covers `adapter.requestsNeeded()` plus in-flight reservations. A slot the adapter flags in `TerritoryPriceState.problems` is never planned or applied against. Adapters (`adapter.ts`) implement `fetchState`, `resolvePricePoints`, `apply`, optional `applyMany`/`batchKey`, and `inverse`; for offers, optional `fetchOffers`, `applyOffer` and `offerRequestsNeeded`.
- **Apple adapter**: subscriptions only in Phase 1. Reads prices with `listSubscriptionPriceEntries` (relationships only, no fallbacks; two future prices in a territory become a problem, never a pick). Snaps to each territory's live price points (`listSubscriptionPricePointsByTerritory`, limit 8000, territory from the relationship). A scheduled price is replaced create-first, delete-after; a budget refusal on the delete fails the op. `startDate` is always `YYYY-MM-DD`.
- **Offers (Phase 2a, read-only)** (`offers.ts`, `offer-derivation.ts`): `OfferSpec` (kinds `apple.intro|promo|offerCode|winBack`, `play.offer` reserved), ISO durations (`P1Y`; Apple enums map via `appleDurationToIso`), and the `StoreOffer` read model. `deriveOfferPrices` applies `percentOfCurrent` per territory: `current x percent` (`perPeriod`) or `x offerDuration/billingPeriod` (`totalOverDuration`; weeks vs months is refused), snapped to that territory's own ladder (ties lower) against the exact fraction (percent has at most 4 decimals), with flags (`NOT_BELOW_CURRENT`, `NO_PRICE_POINT`, deviation above 5% as a warning; weeks vs months skip the below-current check with `SPAN_NOT_COMPARABLE`). Without a basis, pay-up-front offers use `totalOverDuration` (`defaultOfferBasis`). `AppleAdapter.previewOffer` refuses a free trial, unknown mode/duration or an impossible ratio before reading base prices or ladders. Pay-up-front promotional offer prices are the total for the whole duration (confirmed on a real account: `totalOverDuration` of a 1-year offer on an annual subscription matched every territory).
- **Apple offer reads** (`lib/apple-connect/offers.ts`, `AppleAdapter.fetchOffers/fetchOffer/previewOffer`): offer lists without `include=prices` (capped at 50), then each offer's `/prices` list (limit 200, paginated) with `include=territory,subscriptionPricePoint`. Territory, price point and currency come only from relationships and included resources; anything missing is a `territoryProblems`/`problems` entry. Intro offers (one resource per territory) are grouped by their terms. Route: `GET /api/apple/subscriptions/[id]/offers` (numeric subscription ID, one `RequestBudget` per request).
- **Offer ops (Phase 2b)** (`offer-ops.ts`, `offer-plan.ts`): `createOffer`, `updateOfferPrices` (promotional offers only), `deactivateOffer`/`activateOffer` (offer codes: `active`; intro and win-back: end date; never promos), `deleteOffer` (never offer codes: the API has no DELETE). Each op targets `{ product, offer: { kind, key } }` with `before`/`after` `OfferState` (terms + per-territory prices) and `computeOfferIdempotencyKey`. Offers are found by key (promo `offerCode`, offer code `name`, win-back `offerId`); intro offers by `introOfferKey` (terms + start date) and judged territory by territory (`classifyOfferOp`), so a half-done intro create resumes with only the missing territories. `planOfferChanges` (pure) and `AppleAdapter.planOffers` (reads) turn `OfferSpec`s into a ChangeSet plus `OfferPlanEntry` previews (derivation rows, changes, refusals: `PROMO_OFFER_CAP` (10), `TERMS_IMMUTABLE`, `PRICES_IMMUTABLE`, `MISSING_SETTINGS`, overlapping intro windows as `OFFER_CONFLICT` skips). `pricingkit.offerPlanSpec` holds several offers (e.g. one per product); keys must be unique per kind. `planOfferLifecycle` plans end/reactivate/delete. Re-pricing never removes a territory. The executor applies offer ops only with `confirm === changeSetHash(plan)` (`ConfirmationRequiredError` before any read), and `deleteOffer` only with `force.deleteOffers` (`REDEMPTIONS_UNCHECKED`: the API reports no redemptions). Undo also reverses offer ops that failed after an attempt was sent (they may have taken effect) and lists caveats in `notReversible` (redeemed codes, deleted offers' history).
- **Apple offer writes** (`lib/apple-connect/offer-writes.ts`, `AppleAdapter.applyOffer`): bodies follow OpenAPI 4.5.1 and are checked against `src/lib/apple-connect/__tests__/fixtures/offer-write-requests.schema.json` (derived from the spec: names, required fields, enums). Inline prices use local IDs `${price-<alpha3>}` (confirmed on a test app for promo creates). A promo price replace sends the full list (Apple replaces the whole list with it: confirmed, see Testing): unchanged territories by their price ID (`StoreOffer.priceRefs`), the rest inline. Refusals are rewritten by `explainOfferRefusal` (status and code kept; a spent budget stays `BUDGET_EXCEEDED`). Routes: `POST .../offers/plan` (reads only) and `POST .../offers/apply` (promotional offer creates and price updates only, `op.target.offer.kind === 'apple.promo'`, on this subscription, signed-in app, `confirm` = plan hash). The web flow keeps nothing server-side and has no resume or undo; the dialog offers the plan and run log as downloads (named `<plan id>.json` / `.run.json`, the CLI's defaults) and shows the CLI `apply --resume` and `undo` commands.
- **App ownership** (`lib/apple-connect/ownership.ts`): API keys are team-wide, so every write path checks the subscription belongs to the app: `SubscriptionOwnership` resolves the app by exact bundle ID (`GET /apps?filter[bundleId]`), its groups (`GET /apps/{id}/subscriptionGroups`) and the subscription's group (`GET /subscriptions/{id}?include=group`; spec 4.5.1 has no group -> app relationship). `AppleAdapter.verifyProduct` runs it in `planOffers`/`planOfferLifecycle`, and the executor calls `adapter.verifyProduct` per product before reading or writing (`APP_MISMATCH`, 409). The offer routes check up front; the subscription GET (numeric ID), PATCH/DELETE, price-points, price-points/batch, offers GET, clear-scheduled and `/api/export` (numeric ID) routes use `assertSubscriptionInApp` (DELETE also requires the price to be the subscription's). Routes that take an Apple subscription `[id]` for a path accept only a numeric ID (`appleInternalIdSchema`), and every path segment in `src/lib/apple-connect` is `encodeURIComponent`-ed. `AppleAdapter.assertApp` refuses credentials without a bundle ID. The in-app purchase and app price routes are scoped by construction (the product is found by SKU in the session app's own list; the price schedule names the session app), pinned by tests.
- **Intro offer resources:** an intro create records `createdIds` (territory -> resource ID) in the run log, also on a partial failure (`partialResponse` on the error). Resume and verify use them; undo deletes only those resources (`OfferState.storeRefs`) and lists territories with no recorded ID as not reversible. Without IDs, an intro offer is found by terms + start date, and "no offer with these terms but an overlapping one" counts as changed since planning, never done. Undo skips an offer create only when its single attempt was refused with a 4xx (after a timeout, a later 409 keeps it in undo). Before each send the executor records the intro territories it is about to send in the run log (`response.sentTerritories`, merged across attempts); a resume that finds intro territories of a create already in place after an attempt adds their IDs to `createdIds` (`foundOnResume`) only if they were sent, so undo deletes them and never an identical offer someone else made. Run logs from before this change have no `sentTerritories`, so nothing is adopted from them (undo lists those territories as not reversible). The confirm-mismatch error never includes the plan's hash (executor, route, CLI); `plan` and `diff` print it. `src/app/api/__tests__/write-routes-auth.test.ts` checks every write route takes credentials from the session.
- **Sync engine (Phase 4)** (`offer-sync.ts`, `AppleAdapter.readRuleProducts/planOfferSync`): rules live in a checked-in `pricingkit.offerRules` v1 file (`parseOfferRules`: product, kind, key (offer key or store ID), `pricing` percentOfCurrent with optional basis (defaults by mode), `territories`, `syncWithBase`, `deviationThreshold`; Apple rules for a bundleId app, `play.offer` rules for a packageName app (see Play offers); one entry per offer). `planOfferSync` re-derives `syncWithBase` offers against `projectBasePrices(state, baseOps)` (setPrice targets; schedulePrice only under `deriveNow`), only in territories the offer already has, and appends `updateOfferPrices` ops after the base plan's ops (same IDs) with `dependsOn` = that product's base ops in scope. Offer codes, win-back and intro offers that would change, missing/unreadable offers, free trials, and territories with scheduled base ops under the default `scheduledBase: 'hold'` (held: they keep their offer price, the op covers and depends on the other territories only) become `ChangeSet.manualActions` (`PRICES_IMMUTABLE`, `OFFER_NOT_FOUND`, `OFFER_UNREADABLE`, `RULE_NOT_APPLICABLE`, `BASE_SCHEDULED`); never an op that deletes or re-creates. `AppleAdapter.readRuleProducts` reads price points only for offers a rule can price (found, known terms, not a free trial) and only the offer's territories within the rule's list, recorded in `ladderTerritories`; sync skips products with no `syncWithBase` rule (a `syncWithBase: false` rule is listed as `notSynced` and never read). 1 subscription x 175 territories = 25 requests (test-pinned). There is no drift check (removed): a sync plan with no ops is the "in step" answer. Executor: units run in rounds: a unit runs once nothing it `dependsOn` is still queued; within a round base-price units go before offer units. An op whose dependency failed in this pass fails `BASE_NOT_APPLIED` (offer op) / `OFFER_NOT_APPLIED` (base op) with nothing sent; a dependency that didn't run in this pass (stopped, or failed in an earlier pass and not retried) leaves it untouched. `checkChangeSetRules`: `dependsOn` links a base op and an offer op of the same product, one level deep (the target has no `dependsOn`), so no cycles. `buildUndoChangeSet` reverses the edges: the base reverts of a sync run depend on the offer revert, so offers revert first and a base price isn't reverted under an offer whose revert failed.

Play op kinds: `createOffer` (POST create, then `:activate` when `after.state` is ACTIVE; both POSTs use `googlePlayFetch`'s `retryOnlyRateLimited` (429 only; anything else is final and `retryable: false`); a 409 counts only if the offer read back is exactly `after`; the response / `partialResponse` records `createSent`, `created`, `activationSent`, `activated` (true / false for a 4xx refusal / 'unknown'); a matching DRAFT classifies as `ready` with `pending: ['activate']`), `updateOffer` / `updateOfferPrices` (PATCH, `updateMask` = `changedPlayOfferFields`, regions change -> phases too), `activateOffer`, `deactivateOffer`, `deleteOffer` (drafts only, needs `force.deleteOffers`). Create/patch need `op.regionsVersion`, planned from `convertRegionPrices().regionVersion` (Play's Subscription resource has no regionsVersion field) or the spec's `play.regionsVersion`. Undo (`invertPlayOfferOp(op, { failed, response })`): created ACTIVE and ok -> deactivate (never delete); failed before any activation was sent, or activation refused -> delete the (possible) DRAFT (skipped if absent); activation without an answer or nothing recorded -> notReversible. `run.ts`: a Play create with `createSent` is never "refused", and no op whose error has `clientAttempts > 1` (client retried) is. Plans: existing offers' state/eligibility/tags before -> after in `PlayOfferPreview.before`/`tagChanges`/`eligibilityChange` and `PlanSummary.playOffers`; named warnings; removing a tag needs `play.allowTagRemoval` (else `TAG_REMOVAL`); relativeDiscount other than 0.5 warns (unconfirmed meaning); percentOfCurrent regions beyond `play.deviationThreshold` / rule `deviationThreshold` are errors (`DEVIATION_ABOVE_THRESHOLD` skip, CLI `plan` exits 1); fixed/absolute amounts must fit the currency scale; sync turns `DISCOUNT_TOO_LARGE` into a `RULE_NOT_APPLICABLE` manual action. Reading (`parsePlayOffer`) is strict: unknown fields, a region priced two ways, a phase missing a region, a bad fraction -> `problems` / `territoryProblems`, and such an offer is never written (classify -> drifted, plan -> OFFER_UNREADABLE). Plans: `planPlayOfferChanges` (pure; one phase per spec: PAY_UP_FRONT = 1 recurrence, PAY_AS_YOU_GO = `periods`; eligibility required; regions = base plan regions with availability mirrored; no otherRegionsConfig on create; existing offer: same phase terms -> patch (regions kept, `updateOfferPrices` if only prices change), other terms -> `TERMS_IMMUTABLE`, matching draft/inactive -> `activateOffer`) and `PlayAdapter.planOffers` (reads; percentOfCurrent targets via `playPercentTargets`, priced by `resolvePricePoints`), entries carry `play` previews (eligibility, phases, tags, rows: base price, prorated base, offer price (estimated for discounts), discount). `planPlayOfferLifecycle` for activate/deactivate/delete. Sync (`planPlayOfferSync`; rule `pricing` percentOfCurrent | fixed | play.relativeDiscount | play.absoluteDiscount, optional `phase`): relative discounts follow the base (sync entry action `followsBase`), percentOfCurrent re-derived against `projectedPlayBases` (setPrice ops) and snapped by the adapter (`playRuleTargets` -> `snapRules`), fixed/absolute patched back only when they differ, regions no longer below the base skipped. App check: `adapter.verifyApp(changeSet.app)` runs in the executor before anything (Play: packageName; Apple: bundleId), `PlayAdapter.verifyProduct` reads the subscription from the package (once per subscription) and requires the base plan. Offers only on auto-renewing base plans. Route: `GET /api/subscriptions/[id]/offers[?basePlanId]` (read-only, session app, own budget); UI: `PlaySubscriptionOffers` on the Google subscription page.

- **Confirmed on a real account (read-only, Oct 2026):** free-trial intro offer prices have no price point (read as free); a pay-up-front promotional offer's price is the total for its whole duration; offer list/price reads, strict relationships, pagination and budget work as built. Creating a 175-territory promotional offer in one request (inline `${...}` price IDs) worked outside PricingKit.
- **Confirmed on a test app with PricingKit writes (Oct 2026):**
  1. Inline local price IDs (`${price-<alpha3>}`) work for promotional offer creates.
  2. The promotional offer price PATCH **replaces** the whole price list with the one sent: after the PATCH the offer had 175 prices and no duplicates.
  3. A promotional offer create can answer a transient 500 having created nothing. Resume re-read the offer, didn't find it and created it once (the design: creates retry only 429, and a resume looks the offer up by key before sending).
  4. The confirm gate, idempotent re-apply (`ALREADY_AT_TARGET`), undo of a re-price, and undo of a create all worked. Undoing a create was refused with `REDEMPTIONS_UNCHECKED` without `--force-delete` and deleted the offer with it.
- **Not yet confirmed (check in the write test against a test app):** what `duration` means for pay-as-you-go offers; the 10-active-promotional-offer cap; whether free-trial prices are accepted without a price point on create; the win-back inline price relationships (the spec lists none on `WinBackOfferPriceInlineCreate`); whether Apple accepts an end date in the past or reuse of a deleted offer's key; intro window end dates as exclusive; whether an intro offer created without a start date reads back with one (startDate read-back; the fake can simulate it with `fillIntroStartDate`). `fake-apple-offer-store.ts` encodes the PATCH-replaces and cap assumptions.

## Environment Variables

```
ENCRYPTION_KEY              # Required outside `next dev`: base64 of >= 32 bytes, >= 16 distinct (openssl rand -base64 32). Encrypts session cookies
SESSION_VERSION             # Optional: set or change it to sign everyone out (it is part of every session's authenticated data)
OPEN_EXCHANGE_RATES_APP_ID  # Optional operator key for currency conversion; users can also save their own in Settings
TRUSTED_CLIENT_IP_HEADER    # Optional: proxy header with the real client IP (cf-connecting-ip, x-real-ip, x-forwarded-for).
                            # Only set it when every request passes that proxy; never trust client IP headers otherwise.
```

On Cloudflare Workers set these as Worker secrets; for `npm run preview` put them in `.dev.vars`.
